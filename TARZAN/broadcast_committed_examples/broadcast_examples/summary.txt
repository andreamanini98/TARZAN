ghost_signal: Sender Done location is reachable while Receiver Updated location is not reachable due to an unsatisfiable boolean guard. This behavior correctly reflects the fact that the sender can fire a broadcast transition even if no receiver can synchronize on that.

atomicity: Checker Success location is reachable iff integer variable x is updated by all the 3 receivers. It can be tested (with a simple boolean guard on the checker transition) that it is not possible that just 1 or 2 receivers synchronize on the sender broadcast transition since all the receivers can (and hence must) fire. Moreover, the Checker's internal transition cannot fire between the variable update of the broadcast (e.g. with x = 2 after 2 updates out of 3) since it is atomic.

combinatorial_transitions: Checker Success location is reachable iff boolean guard tries values that can be the result of all the combinations between Receiver1 and Receiver2 neatly: 2, 5, 6, 15. All other values on the boolean guard (0 excluded since the checker intern transition can fire before the broadcast) make the Done location unreachable.

guard_check: Checker Success location is reachable iff both the receivers' broadcast transitions fire. They both have a boolean guard that is respected only before the start of the transition but not in the meanwhile. This proves that boolean (and clock) guards are checked only before the start of the broadcast transition but not during it (i.e. an intermediate receiver can break other synchronizing receivers guards without consequences since the overall transition is atomic. Nevertheless, this isn't true if the sender breaks the guards, since this influences the receivers' participation).
